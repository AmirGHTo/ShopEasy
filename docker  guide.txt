


Simulate multiple instances:

# Scale to 3 instances
docker-compose up --scale order=3 --no-recreate

docker-compose up --scale order=5

# First time
docker-compose up --build --scale order=3

# Scale up while running (no downtime)
docker-compose up --scale order=5 --no-recreate

# Scale down while running
docker-compose up --scale order=2 --no-recreate

****************************************************
docker-compose down --remove-orphans
docker-compose build --no-cache identity
docker-compose up

docker-compose down -v --remove-orphans


docker-compose stop RabbitMQ
*********************************************
docker-compose down --remove-orphans
docker volume rm shopeasy_postgres-data
docker-compose up

Now create migrations for the remaining services
cd src\Services\ShopEasy.PaymentService
dotnet ef migrations add InitialCreate --output-dir Data/Migrations

cd ..\ShopEasy.ProductService
dotnet ef migrations add InitialCreate --output-dir Data/Migrations

cd ..\..\Identity\ShopEasy.Identity
dotnet ef migrations add InitialCreate --output-dir Data/Migrations

Each one will show the same HostAbortedException — that's fine, just confirm each ends with Done.
Then rebuild:

docker-compose down -v --remove-orphans
docker-compose up --build
**************************************************************************
What Happens for Future Schema Changes
Say next week you implement the Saga pattern and need a new SagaState table:
bash# 1. Add the entity to your DbContext
# 2. Create the migration
dotnet ef migrations add AddSagaState --output-dir Data/Migrations

# 3. Rebuild and deploy
docker-compose up --build order
